# The simulation frame takes the page width

Supersedes `0018`. Refines `0005` for layout only. The frame, its height measurement and its tab order keep their meaning.

## Decision

- The Halaman Simulasi frame takes the full content width of the page (`.wrap`, up to 1440px). No information column sits beside it.
- The catalogue description sits above the frame. The related simulations sit below the frame.
- Document order is breadcrumb, heading, description, frame, new-tab link, related list.
- Inside `Angka Bulat dan Garis Bilangan`, from a frame width of 760px the canvas and its readouts sit on the left and the controls and presets on the right. This follows the Stitch simulation screen, where the control panel is the right-hand column. Below 760px the sections stack in document order, and the DOM order is unchanged, so tab order is the same.
- Other simulations keep their single-column layout until each one is changed.

## Why

- A reader changes a control and then reads the result. At 1280px the frame beside the information column was about 784px wide. That is too narrow for two columns inside the simulation, and the controls sat below the first screen.
- At full width the simulation's controls sit beside the canvas, in view at the same time, on a 1280px by 900px screen.

## Consequences

- `0018` no longer applies. Its information column is removed.
- The two-column layout inside the simulation is a manual edit to one simulation file. It is lost if the simulation is regenerated by simula-w, as the other edits to that file are.
- A simulation's text no longer has a narrow column next to it. The description is short by design (`0005`), so it does not need that column.
